# 报警处置规划外部接口文档

> 版本：v2.1  
> 适用对象：外部报警系统、资源/边界/摄像头/智能设备数据提供方、指挥调度系统  
> 调用方式：HTTP REST + 异步任务查询，可选 SSE 进度流  
> 自定义接口基础地址：`http://192.168.0.192`  
> 现有底座服务地址：`http://192.168.0.27`，承载 weitong、TrajRP、dispatch 等能力  
> 新流程 SVG：[`alarm-disposal-async-planning-flow.svg`](./alarm-disposal-async-planning-flow.svg)

本文档说明外部系统如何把 `weitong` 中已有的处置编排能力抽成外部可触发的报警处置规划接口。新流程保留 `weitong` 作为事件、资源、边界、摄像头、智能设备、调度结果的业务底座；资源、边界、摄像头和智能设备数据不在本文档中定义获取方式，需由对接方提供可访问的接口或数据库连接。警报触发时只提交轻量报警信息，系统按现有异步任务模式返回 `taskId`，后台生成处置方案。

第一版范围：

- 警报触发采用异步任务：立即返回 `taskId`，后续轮询或订阅 SSE。
- 资源、边界、摄像头、智能设备由对接方提供接口或数据库连接；本文档不约定其采集/同步实现。
- 警报触发时只传 `externalAlarmId`、坐标、时间、发现设备等轻量字段。
- 第一版路径规划采用 TrajRP Method2 候选点预测；由于真实路径规划模型缺失，暂不承诺真实可通行路径规划可跑通。
- 处置结果返回每个资源的目标点和可执行路线点 `routeWaypoints`；第一版可为资源当前位置到目标点的两点线。
- 嫌疑人轨迹预测第一版只返回 Method2 候选点 `predictedCandidates`，后续再升级为完整预测路径。
- 规划结果是触发时刻的点位快照，不自动代表持续追踪命令，也不会自动下发设备控制指令。

---

## 1. 总体架构

```text
外部资源/边界/摄像头/智能设备系统
  -> 提供可访问接口或数据库连接

外部报警系统
  -> POST /alarm/disposal
  -> 立即获得 taskId
  -> GET /alarm/disposal/{taskId} 或 /alarm/disposal/{taskId}/stream 获取结果

后台处置规划任务
  -> 创建/复用 suspect_event
  -> 通过对方接口/数据库读取资源、边界、摄像头、智能设备快照
  -> TrajRP Method2 生成候选预测点
  -> dispatch 完成资源分配
  -> 生成资源目标点与 routeWaypoints，并返回统一处置方案
```

关键设计结论：

| 决策点 | 结论 |
|---|---|
| 事件与结果存储 | 保留 `weitong` 作为落库中心 |
| 外部数据方式 | 对接方提供资源/边界/摄像头/智能设备接口或数据库连接；警报触发时只传 alarmId/坐标 |
| 处置规划返回 | 每个处置资源返回目标点和 routeWaypoints；第一版可为两点路线 |
| 嫌疑人预测 | 第一版使用 Method2 返回候选点，后续升级完整预测路径 |
| 异步模型 | 沿用现有 `tasks` 模式：创建任务、查询任务、SSE 进度 |

## 2. 接口概览

| 接口 | 方法 | 路径 | 完整地址 | 说明 |
|---|---|---|---|---|
| 触发报警处置 | `POST` | `/alarm/disposal` | `http://192.168.0.192/alarm/disposal` | 提交轻量报警信息，异步生成处置方案 |
| 查询处置任务 | `GET` | `/alarm/disposal/{taskId}` | `http://192.168.0.192/alarm/disposal/{taskId}` | 查询任务状态、步骤和最终结果 |
| 订阅处置进度 | `GET` | `/alarm/disposal/{taskId}/stream` | `http://192.168.0.192/alarm/disposal/{taskId}/stream` | 可选 SSE 流，语义对齐现有 `/tasks/{taskId}/stream` |

所有请求和响应默认使用 `Content-Type: application/json`。SSE 接口使用 `text/event-stream`。

## 3. 对接方需提供的数据能力

资源、边界、摄像头和智能设备不是本接口主动采集的数据。正式对接前，需要由对接方提供稳定的数据访问方式，二选一或同时提供：

- HTTP/REST 接口：提供资源目录、资源实时位置、边界、摄像头、智能设备点位等查询能力。
- 数据库连接：提供只读库表、视图或存储过程，允许处置规划任务按告警触发时刻读取快照。

建议最小数据范围：

| 数据 | 必要字段 | 用途 |
|---|---|---|
| 处置资源 | `id`、`type`、`lng`、`lat`、`speed`、`available` | 资源调度输入 |
| 资源实时位置 | `resourceId`、`lng`、`lat`、`recordTime` | 计算资源到目标点距离和 ETA |
| 边界 | `id`、`name`、`points[{lng,lat,seq}]` | 态势约束、候选点过滤和展示 |
| 摄像头 | `id`、`name`、`lng`、`lat`、`status` | 报警来源、态势展示和盲区参考 |
| 智能设备 | `id`、`type`、`lng`、`lat`、`status` | 报警发现设备、辅助态势展示 |

对接要求：

- 数据坐标统一使用 WGS-84 经纬度。
- 对接方需要说明接口鉴权、分页、更新时间字段、状态枚举和异常返回格式。
- 若提供数据库连接，需要给出处置规划服务可访问的连接地址、库表字段、只读账号和网络白名单。
- 规划任务只在告警触发时读取一份快照；实时持续追踪需要后续通过同一 `eventId` 再触发刷新规划。

## 4. 触发报警处置

### 4.1 接口说明

外部报警系统发现嫌疑人或异常事件后，只提交轻量警报。系统收到后立即创建异步任务并返回 `taskId`；后台任务通过对接方提供的接口或数据库连接读取资源、边界、摄像头、智能设备快照，完成 Method2 候选点预测和资源调度。第一版不依赖真实路径规划模型。

该接口语义对齐现有 `/tasks` 异步模式：

1. HTTP 请求不等待完整规划结果。
2. 返回 `taskId` 与 `status=pending`。
3. 后台任务更新为 `running`、`completed` 或 `failed`。
4. 调用方通过查询接口或 SSE 接口获取进度和结果。

### 4.2 请求

```http
POST http://192.168.0.192/alarm/disposal
Content-Type: application/json
```

请求参数：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `externalAlarmId` | string | 是 | 外部系统报警唯一 ID，用于幂等和追踪 |
| `longitude` | float | 是 | 报警经度，WGS-84 |
| `latitude` | float | 是 | 报警纬度，WGS-84 |
| `eventTime` | string | 是 | 发生时间，格式 `yyyy-MM-dd HH:mm:ss` |
| `currentDeviceId` | string | 是 | 发现报警的设备 ID，如摄像头或便携设备 |
| `personId` | string | 否 | 目标身份 ID |
| `currentTrackId` | string | 否 | 当前轨迹 ID |
| `personType` | string | 否 | 目标类型，如 `person`、`vehicle` |
| `personAction` | string | 否 | 动作，如 `walking`、`running` |
| `personDistance` | float | 否 | 与发现设备距离，单位米 |
| `imageUrl` | string | 否 | 抓拍图片 URL |
| `priority` | string | 否 | `low` / `normal` / `high` / `critical`，默认 `normal` |
| `reuseEventId` | int/string | 否 | 可选；用于刷新同一事件的处置规划，不创建重复事件 |

请求示例：

```json
{
  "externalAlarmId": "ALARM_20260706_0001",
  "longitude": 87.123456,
  "latitude": 43.123456,
  "eventTime": "2026-07-06 10:30:00",
  "currentDeviceId": "CAM_001",
  "personType": "person",
  "personAction": "walking",
  "imageUrl": "https://example.com/snap.jpg",
  "priority": "high"
}
```

### 4.3 成功响应

推荐 HTTP 状态码：`201 Created`。响应体：

```json
{
  "taskId": "9b8dd7dd-2f8e-4b4a-ae3a-6efbc2e65d0d",
  "status": "pending",
  "eventId": 12345
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `taskId` | string | 异步任务 ID，对齐现有任务系统 UUID |
| `status` | string | 初始为 `pending` |
| `eventId` | int/string | 已创建或复用的 `weitong suspect_event` ID；如果创建事件也放入后台，可在查询结果中返回 |

### 4.4 错误响应

```json
{
  "error": "longitude and latitude are required"
}
```

常见错误：

| HTTP 状态 | 说明 |
|---|---|
| `400` | 请求参数缺失或格式错误 |
| `409` | `externalAlarmId` 已存在且不允许重复触发 |
| `500` | 系统内部错误 |


## 6. 订阅处置进度 SSE

该接口对齐现有 `/tasks/{taskId}/stream` 语义，适合前端或外部指挥系统展示任务进度。

```http
GET http://192.168.0.192/alarm/disposal/{taskId}/stream
Accept: text/event-stream
```

事件示例：

```text
event: update
data: {"taskId":"9b8dd7dd-2f8e-4b4a-ae3a-6efbc2e65d0d","status":"running","step":"route_generation","message":"正在为已分配资源生成目标点和路线点"}

event: completed
data: {"taskId":"9b8dd7dd-2f8e-4b4a-ae3a-6efbc2e65d0d","status":"completed"}
```

推荐步骤枚举：

| step | 说明 |
|---|---|
| `create_suspect_event` | 创建或复用 `suspect_event` |
| `load_context_snapshot` | 通过对接方接口或数据库连接读取资源、边界、摄像头、智能设备快照 |
| `blind_spot_completion` | 盲区补全；轨迹点不足时跳过 |
| `trajectory_prediction` | 使用 Method2 生成嫌疑人候选预测点 |
| `resource_allocation` | 资源调度 |
| `route_generation` | 为每个处置资源生成目标点和路线点 |
| `persist_result` | 写入任务结果与 `patrol_allocation` |

## 7. 后台处置规划流程

### 7.1 事件建档

系统根据轻量报警创建或复用 `weitong` 事件：

- 创建事件：`POST /dev-api/api/v1/external/suspect/events`
- 更新状态：`PUT /dev-api/api/v1/external/suspect/events/{eventId}/status`
- 追加轨迹：`POST /dev-api/api/v1/external/suspect/events/{eventId}/positions`

映射关系：

| 报警字段 | `weitong` 字段 | 说明 |
|---|---|---|
| `longitude` | `startLng` / 轨迹点 `lng` | WGS-84 |
| `latitude` | `startLat` / 轨迹点 `lat` | WGS-84 |
| `eventTime` | `createTime` / `recordTime` | 报警时间 |
| `currentDeviceId` | `description` | 记录来源设备 |
| `externalAlarmId` | `description` 或扩展字段 | 用于幂等追踪 |

### 7.2 上下文快照

规划任务通过对接方提供的数据访问方式读取快照：

- 资源目录：资源 ID、类型、速度、可用状态。
- 资源实时位置：经纬度、更新时间。
- 边界：边界线或区域点序列。
- 摄像头：摄像头点位和在线状态。
- 智能设备：报警发现设备、辅助态势设备和在线状态。
- active 调度：如对接方已有资源占用状态，需要一并提供，用于避免资源冲突。

### 7.3 Method2 候选点预测

第一版使用 TrajRP Method2 快速候选点预测：

```http
POST http://192.168.0.27/trajrp/api/v1/prediction/trajectory_forecast
```

策略：

- 历史轨迹点少于 2 个：跳过复杂预测，直接以报警点为目标。
- 历史轨迹点不少于 2 个：调用 TrajRP Method2，返回 `predictedCandidates`。
- 第一版不承诺嫌疑人完整预测路径；完整路径作为后续增强。
- 第一版不调用真实路径规划服务；原因是当前真实路径规划模型缺失，无法保证端到端跑通。

### 7.4 资源调度与路线点生成

调度服务调用：

```http
POST http://192.168.0.27/dispatch/api/v1/dispatch/resource_allocation
```

关键请求参数：

```json
{
  "coord_system": "lnglat",
  "event_id": 12345,
  "resources_available": [],
  "target_info": {
    "trajectory": [
      {"lng": 87.123456, "lat": 43.123456, "timestamp": 0},
      {"lng": 87.124000, "lat": 43.124000, "timestamp": 30}
    ],
    "intent_classification": "escape"
  },
  "rules": {
    "require_capture_unit": true,
    "capture_min_units": 1,
    "dispatch_mode": "two_point_split",
    "min_dispatch_units": 2,
    "max_drone_units": 1
  }
}
```

调度服务内部会：

1. 过滤已被其他 active 事件占用的资源。
2. 生成资源分配方案。
3. 为每个资源生成目标点。
4. 为每个资源生成 `routeWaypoints`；第一版通常为“资源当前位置 -> 目标点”的两点线。
5. 写入任务结果；是否同步到 `patrol_allocation` 或外部系统由实际对接方式决定。

后续如果补齐真实路径规划模型，可将 `routeWaypoints` 从两点线升级为真实可通行路径。

## 8. 降级策略

| 场景 | 降级行为 |
|---|---|
| 外部资源接口或数据库不可访问 | 任务失败，返回数据源不可用原因 |
| 资源实时位置缺失 | 该资源不参与本轮调度，或按对接方提供的最近位置兜底 |
| 没有历史轨迹 | 不做盲区补全和复杂预测，直接按报警点调度 |
| TrajRP 不可用 | 使用报警点或最近轨迹点作为目标 |
| Method2 无候选点 | 使用报警点或最近轨迹点作为调度目标 |
| 真实路径规划不可用 | 第一版默认生成起点到目标点两点线 |
| 可用资源不足 | `captureFeasible=false`，返回失败原因和已考虑资源数 |
| 同一资源被其他事件占用 | 默认不抢占；高优先级抢占需显式规则 `allow_reassign_active_resources=true` |

## 9. 调用流程示例

```text
1. 对接方预先提供数据访问方式：
   资源/边界/摄像头/智能设备接口
   或只读数据库连接

2. 发生报警：
   POST /alarm/disposal
   -> 返回 {taskId, status: "pending", eventId}

3. 外部系统查询或订阅：
   GET /alarm/disposal/{taskId}

4. 任务完成后展示：
   result.prediction.predictedCandidates
   result.plan[].routeWaypoints
   result.agentSummary
   result.filledPlanText
```

## 10. 字段取值说明

- 经纬度统一使用 WGS-84。
- 时间统一使用 `yyyy-MM-dd HH:mm:ss` 或 ISO-8601；响应中的系统时间可使用 ISO-8601。
- `type` 支持 `drone`、`car`、`dog`、`person`。
- `routeWaypoints` 是处置资源的路线点；第一版通常为资源当前位置到目标点的两点线，不等同于真实可通行路径。
- `predictedCandidates` 是 Method2 嫌疑人候选预测点；第一版不输出完整嫌疑人逃逸路径。
- `captureFeasible=true` 只表示按当前快照可形成处置方案，不表示已经抓获。
- 规划结果是点位快照。如果资源或嫌疑人位置变化，需要用同一 `eventId` 再触发一次刷新规划。
