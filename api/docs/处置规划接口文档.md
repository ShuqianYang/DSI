# 报警处置外部接口文档

> 版本：v1.1  
> 适用对象：外部报警系统开发商  
> 调用方式：HTTP REST，内网部署，无需认证  
> 自定义接口基础地址：`http://192.168.0.192`（默认部署地址，后续如有变更会另行通知）  
> 底层服务基础地址：`http://192.168.0.27`（轨迹预测、代价图、调度等现有服务）

本文档说明外部报警系统如何推送报警、查询处置规划结果，以及需要外部配合提供的边境/摄像头数据。

- 自定义接口（`/alarm/disposal`、`/trajrp/...` 对外暴露版本）完整地址 = `http://192.168.0.192 + 接口路径`
- 底层服务接口（`/trajrp/...`、`/api/v1/analysis/...` 原服务）完整地址 = `http://192.168.0.27 + 接口路径`

---

## 1. 接口概览

| 接口 | 方法 | 路径 | 完整地址 | 说明 |
|---|---|---|---|---|
| 触发报警处置 | `POST` | `/alarm/disposal` | `http://192.168.0.192/alarm/disposal` | 外部系统推送报警，系统异步生成处置规划 |
| 查询处置结果 | `GET` | `/alarm/disposal/{taskId}` | `http://192.168.0.192/alarm/disposal/{taskId}` | 使用 `taskId` 轮询任务状态和结果 |
| 轨迹预测（可选） | `POST` | `/trajrp/api/v1/prediction/trajectory_forecast` | `http://192.168.0.27/trajrp/api/v1/prediction/trajectory_forecast` | 独立调用轨迹预测服务 |
| 代价图生成（内部依赖） | `POST` | `/api/v1/analysis/passage_cost` | `http://192.168.0.27/api/v1/analysis/passage_cost` | 生成真实通行代价图 |

所有接口请求/响应均为 `Content-Type: application/json`。

## 2. 触发报警处置

### 2.1 接口说明

外部报警系统发现嫌疑人或异常事件后，调用本接口提交报警信息。系统收到后会立即返回一个 `taskId`，并在后台完成轨迹预测、资源调度、轮询分配等流程。外部系统随后通过「查询处置结果」接口轮询获取最终规划。

### 2.2 请求

```http
POST http://192.168.0.192/alarm/disposal
Content-Type: application/json
```

#### 2.2.1 请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `longitude` | float | 是 | 报警经度，WGS-84 |
| `latitude` | float | 是 | 报警纬度，WGS-84 |
| `eventTime` | string | 是 | 发生时间，格式 `yyyy-MM-dd HH:mm:ss` |
| `currentDeviceId` | string | 是 | 发现报警的设备 ID |
| `personId` | string | 否 | 目标身份 ID |
| `currentTrackId` | string | 否 | 当前轨迹 ID |
| `personType` | string | 否 | 人员类型，例如「迷彩服」 |
| `personAction` | string | 否 | 动作，例如「行走」 |
| `personDistance` | float | 否 | 与设备距离，单位米 |
| `imageUrl` | string | 否 | 抓拍图片 URL |
| `previousDeviceId` | string | 否 | 上一跳设备 ID |
| `previousTrackId` | string | 否 | 上一跳轨迹 ID |

#### 2.2.2 请求示例

```json
{
  "longitude": 87.123456,
  "latitude": 43.123456,
  "eventTime": "2026-07-02 14:30:00",
  "currentDeviceId": "CAM_001",
  "personType": "迷彩服",
  "personAction": "行走",
  "imageUrl": "https://example.com/snap.jpg"
}
```

### 2.3 响应

#### 2.3.1 成功响应

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `200` 表示成功 |
| `msg` | string | 状态描述 |
| `data` | object | 包含 `taskId` |
| `data.taskId` | string | 任务唯一标识，用于后续轮询 |

```json
{
  "code": 200,
  "msg": "ok",
  "data": {
    "taskId": "task_202607021430001"
  }
}
```

#### 2.3.2 错误响应

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 非 200 错误码 |
| `msg` | string | 错误描述 |
| `data` | object | 通常为 `null` 或包含详细校验错误 |

```json
{
  "code": 400,
  "msg": "longitude and latitude are required",
  "data": null
}
```

### 2.4 错误码

| 错误码 | 说明 |
|---|---|
| `200` | 成功 |
| `400` | 请求参数错误 |
| `500` | 系统内部错误 |

## 3. 查询处置结果

### 3.1 接口说明

使用触发接口返回的 `taskId` 查询任务执行状态和最终处置规划。建议在触发后每隔 2 秒轮询一次，最多轮询 30 次（约 60 秒）。

### 3.2 请求

```http
GET http://192.168.0.192/alarm/disposal/{taskId}
```

### 3.3 响应

#### 3.3.1 成功响应

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `200` |
| `msg` | string | 状态描述 |
| `data` | object | 任务详情 |
| `data.taskId` | string | 任务 ID |
| `data.status` | string | 任务状态，见下表 |
| `data.createdAt` | string | 任务创建时间 |
| `data.updatedAt` | string | 任务最后更新时间 |
| `data.result` | object | 当 `status=completed` 时返回，见下方结构 |
| `data.errors` | string[] | 当 `status=failed` 时返回 |

任务状态枚举：

| 状态 | 说明 |
|---|---|
| `pending` | 已收到报警，等待执行 |
| `running` | 正在执行轨迹预测、资源调度、轮询分配 |
| `completed` | 执行完成，`result` 可用 |
| `failed` | 执行失败，`errors` 里有原因 |

#### 3.3.2 `result` 结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `eventId` | int/string | 创建的嫌疑人事件 ID |
| `alarm` | object | 报警位置和时间 `{lng, lat, time}` |
| `trajectoryCount` | int | 历史轨迹点数 |
| `captureFeasible` | boolean | 是否可成功拦截 |
| `plan` | object[] | 资源分配明细 |
| `agentSummary` | string (Markdown) | 智能体总结 |
| `filledPlanText` | string (Markdown) | 硬编码模板填空后的规划文字 |

`plan` 数组元素：

| 字段 | 类型 | 说明 |
|---|---|---|
| `resourceId` | string/int | 资源 ID |
| `type` | string | 资源类型：`drone` / `car` / `dog` / `person` |
| `etaSeconds` | float | 预计到达时间，单位秒 |
| `targetLng` | float | 目标经度 |
| `targetLat` | float | 目标纬度 |
| `action` | string | 动作类型 |

#### 3.3.3 响应示例（运行中）

```json
{
  "code": 200,
  "msg": "ok",
  "data": {

    "createdAt": "2026-07-02T14:30:00Z",
    "updatedAt": "2026-07-02T14:30:04Z",
    "result": null,
    "errors": null
  }
}
```

## 4. 轨迹预测接口

### 4.1 接口说明

本接口为底层轨迹预测服务，可直接对外暴露。外部系统如需单独预测嫌疑人未来位置，可调用本接口。报警处置流程内部也会调用本接口。

当前版本已启用**真实通行代价图**：调用前需要根据事件区域生成代价图，拿到动态 `task_id` 后再调用本接口。

### 4.2 真实代价图生成流程

在调用轨迹预测接口前，系统会按以下步骤生成真实代价图：

1. 根据报警位置和历史轨迹计算事件区域 bbox（`region_bbox`）。
2. 调用代价图服务生成代价图：
   ```http
   POST http://192.168.0.27/api/v1/analysis/passage_cost
   ```
   请求体：
   | 字段 | 类型 | 说明 |
   |---|---|---|
   | `region_bbox` | object | `{min_x, min_y, max_x, max_y}`，经纬度范围 |
   | `object_type` | string | 对象类型，例如 `pedestrian`、`vehicle_suv` |
   | `max_slope_angle` | float | 最大可通行坡度，单位度，例如 `30` |
3. 代价图服务返回动态 `task_id`。
4. 使用该 `task_id` 调用轨迹预测接口。

### 4.3 请求

```http
POST http://192.168.0.27/trajrp/api/v1/prediction/trajectory_forecast
Content-Type: application/json
```

#### 4.3.1 请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `historical_trajectory` | object[] | 是 | 历史轨迹点数组 |
| `historical_trajectory[].x` | float | 是 | 经度 |
| `historical_trajectory[].y` | float | 是 | 纬度 |
| `historical_trajectory[].timestamp` | float | 是 | 时间戳（秒） |
| `historical_trajectory[].speed` | float | 是 | 瞬时速度，单位 m/s |
| `terrain_map` | object | 是 | 地形图与特殊区域 |
| `terrain_map.metadata` | object | 是 | `{height: 100, width: 100}` |
| `terrain_map.terrain_data` | int[][] | 是 | 100×100 二维数组，默认全 0 |
| `terrain_map.special_areas` | object[] | 否 | 边境/摄像头影响区域 |
| `terrain_map.special_areas[].type` | string | 是 | 区域类型，例如 `border` |
| `terrain_map.special_areas[].center` | object | 是 | `{x: 经度, y: 纬度}` |
| `terrain_map.special_areas[].radius` | float | 是 | 影响半径，单位为度 |
| `terrain_map.special_areas[].influence_factor` | float | 是 | 影响因子，例如 `0.8` |
| `prediction_config` | object | 是 | 预测配置 |
| `prediction_config.prediction_method` | string | 是 | 预测方法，使用真实代价图时固定为 `method1` |
| `prediction_config.use_data_speed` | boolean | 是 | 是否使用数据速度，当前固定为 `false` |
| `prediction_config.num_candidates` | int | 否 | 候选点数量，默认 `5` |
| `prediction_config.max_distance` | float | 否 | 最大预测距离，默认 `2000`（米） |
| `prediction_config.minutes_ahead` | float | 否 | 预测未来时间，默认 `0.5`（分钟） |
| `task_id` | string | 是 | 动态生成的代价图任务 ID |

#### 4.3.2 请求示例

```json
{
  "historical_trajectory": [
    {"x": 87.123456, "y": 43.123456, "timestamp": 0.0, "speed": 1.5},
    {"x": 87.123556, "y": 43.123556, "timestamp": 10.0, "speed": 1.5}
  ],
  "terrain_map": {
    "metadata": {"height": 100, "width": 100},
    "terrain_data": [[0] * 100 for _ in range(100)],
    "special_areas": [
      {
        "type": "border",
        "center": {"x": 87.120000, "y": 43.120000},
        "radius": 0.005,
        "influence_factor": 0.8
      }
    ]
  },
  "prediction_config": {
    "prediction_method": "method1",
    "use_data_speed": false,
    "num_candidates": 5,
    "max_distance": 2000,
    "minutes_ahead": 0.5
  },
  "task_id": "task_202607021430001_cost"
}
```

### 4.4 响应

#### 4.4.1 成功响应

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `200` 表示成功 |
| `msg` | string | 状态描述 |
| `data` | object | 预测结果 |
| `data.candidate_points` | object[] | 候选预测点数组 |
| `data.candidate_points[].candidate_id` | int | 候选点 ID |

| `data.candidate_points[].y` | float | 预测纬度 |
| `data.candidate_points[].probability` | float | 概率 |
| `data.candidate_points[].timestamp` | float | 预测时间戳 |
| `data.candidate_points[].distance_meters` | float | 与当前点距离 |

#### 4.4.2 响应示例

```json
{
  "code": 200,
  "msg": "ok",
  "data": {

      {
        "candidate_id": 1,
```

## 6. 调用流程示例

```text
1. 外部报警系统 POST http://192.168.0.192/alarm/disposal
   └─→ 收到 {taskId}

2. 外部报警系统循环 GET http://192.168.0.192/alarm/disposal/{taskId}
   └─→ status=running 时继续等待
   └─→ status=completed 时读取 result

3. 外部报警系统展示 result.plan / agentSummary / filledPlanText
```

建议轮询间隔：2 秒；建议最大轮询次数：30 次（约 60 秒）。

## 7. 附录：字段取值说明

- 经纬度统一使用 WGS-84 坐标系。
- `eventTime` 使用 24 小时制，例如 `2026-07-02 14:30:00`。
- `type` 字段当前支持 `drone`（无人机）、`car`（车辆）、`dog`（机器狗）、`person`（人员）。
- 轨迹预测已启用真实代价图：`prediction_method` 为 `method1`，`task_id` 由代价图服务动态生成。
